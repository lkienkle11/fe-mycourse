## Why

Instructor, admin, and sysadmin dashboard routes deny anonymous visitors with a static "unauthorized" page, but recovering from that denial depends on the visitor noticing the generic "Sign in" button in the header, and that button does not carry a return path, so a successful login never returns the visitor to the page they originally wanted. The login and sign up forms themselves are a plain Zustand-controlled dialog (`authAction` state), not reflected in the URL, so the modal cannot survive a refresh, cannot be deep-linked, and does not integrate with the browser back button. This change makes the dashboard denial flow actually require login (auto-prompt, return to the original page) and gives the login/sign up modal a real, shareable, refresh-safe URL, while keeping the redirect target validated so it cannot be used to send a visitor off-domain.

## What Changes

- Replace the Zustand-dialog login/sign up modal with a route-based modal using a Next.js parallel route (`@modal`) and intercepting routes, mounted once at `src/app/[locale]/layout.tsx` instead of being duplicated across `header.tsx`, `dashboard-layout.tsx`, and `auth-layout.tsx`.
- Add real, `noindex` fallback pages at `/login` and `/signup` (full-page render for direct navigation, hard refresh, or shared links); soft client-side navigation to the same paths is intercepted and rendered as an overlay modal instead.
- Introduce a `next` query parameter (`/login?next=<path>`) as the single source of truth for the post-login return path, replacing the in-memory `nextLink` field on `useAuthStore`. Add and enforce a shared internal-path validator before ever using a `next` value for navigation, rejecting anything that is not a same-origin relative path (protocol-relative `//`, absolute URLs, and backslash-prefixed paths are all rejected).
- Switching between the login and sign up forms inside the modal now navigates between `/login` and `/signup` (via `router.replace`, preserving `next`) instead of toggling a Zustand enum.
- Closing the modal (its close button) triggers the dialog's own closing animation first, then navigates back (`router.back()`), instead of unmounting immediately.
- On a dashboard route (`instructor`, `admin`, `sysadmin`), the existing `unauthorized` denial state (no session) now automatically navigates to `/login?next=<current path>` 500ms after first rendering, opening the modal over that same denial page. The `forbidden` denial state (authenticated but missing permission) is unaffected and never auto-opens the login modal.
- The two existing component-level "sign in to see this" gates (`SignedInHomePage`, `BecomeInstructorPage`) keep their current UI (an inline CTA, not a full-page denial) but switch their trigger from `useAuthStore().openLoginModal(path)` to a navigation to `/login?next=path`, so the whole app uses one modal-opening mechanism.
- Remove the now-unused `authAction` / `nextLink` state and the `openLoginModal` / `openSignupModal` / `closeAllModals` actions from `useAuthStore` once every call site has moved to route navigation. **BREAKING** for any code still importing those store fields/actions.
- A hard navigation to `/login` or `/signup` with a valid `next` (direct URL entry, browser refresh, shared link) now renders as the same intercepted-modal experience as a soft navigation - dimmed backdrop, dialog centered, the `next` page's own real content visible behind it (e.g. the dashboard's `unauthorized` denial page) - instead of a bare full page with no backdrop. A background bridge mounted once app-wide detects this exact case and "bounces" through the background page so Next.js's intercepting-route mechanism engages retroactively. Never bounces to a value that fails the same internal-path validation used elsewhere (no cross-origin background is ever rendered).
- The dashboard's `unauthorized` auto-prompt (500ms timer) now tracks "already prompted this path" as in-memory module state instead of `sessionStorage`, so a genuine browser refresh of the denied page re-arms the prompt (shows the modal again) while a dismiss-triggered remount (closing the modal, landing back on the same denial page) still does not re-trigger it in a loop.

## Capabilities

### New Capabilities
- `auth-route-modal`: the login/sign up experience as a URL-addressable, intercepting-route modal, including the `next` redirect parameter and its validation.

### Modified Capabilities
- `dashboard-access-control`: the `unauthorized` denial scenario changes from "show a static page and wait for the visitor to find the header's sign-in button" to "show the same static page, then automatically prompt the route-based login modal with the denied path as `next`". The `forbidden` scenario, the header/logo visibility rules, and the mobile layout rules are unchanged.

- **Affected code**: `src/app/[locale]/layout.tsx` (new `modal` slot), new `src/app/[locale]/@modal/**`, new `src/app/[locale]/login/page.tsx` and `src/app/[locale]/signup/page.tsx`, `src/store/auth/auth.ts` and `src/hooks/auth/use-auth-store.ts` (state removed), `src/components/common/auth-menu/**` (`LoginSignupPopup`, `LoginContent`, `SignupContent` reused as-is, decoupled from Zustand - see design.md Decision 7), `src/components/common/dashboard/dashboard-layout.tsx` (auto-redirect timer, in-memory prompt tracking), `src/components/common/header/header.tsx` and `auth-layout.tsx` (drop direct `LoginSignupPopup` mount), `src/screen/common/home/signed-in-home-page.tsx`, `src/screen/common/instructor/become-instructor-page.tsx`, `src/hooks/auth/use-oauth-post-auth.ts` (reads `next` instead of store `nextLink`), new `src/hooks/auth/use-auth-modal-background-bridge.ts` and `src/components/providers/auth-modal-background-bridge.tsx` (mounted in `AppProviders`, alongside the existing `AuthConfirmTabSync`/`AuthLogoutTabSync` sync components).
- **New shared utilities, reusing existing conventions rather than inventing new ones** (see design.md Decisions 2-3, 8): `isSafeInternalPath` in `src/lib/security/web/safe-redirect.ts` (alongside the existing `crawl-policy.ts`/`redact-client-payload.ts`), a `useAuthNextParam()` hook mirroring `use-instructor-roster-portfolio-query.ts`'s shape, `buildQueryParams` (`src/lib/utils/url.ts`) for link building, and the already-scaffolded-but-unused `robotsModeForPublicRouteKey`/`robotsPreset` (`src/lib/seo/robots-presets.ts`) for `/login`/`/signup` noindex.
- **Route/i18n constants**: add `login`/`signup` to `PUBLIC_ROUTES` (`src/constants/route.ts`); add `auth.loginPage.pageTitle` / `auth.signupPage.pageTitle` message keys to `src/messages/en.ts` and `vi.ts` (mirroring the existing `auth.confirm.pageTitle` / `auth.logout.pageTitle` shape - the flat `auth.login` / `auth.register` string keys already used as button labels are left untouched).
- **No backend/API changes.** OAuth continues to run through the existing popup + `postMessage` relay (`OAuthPopupCallbackRelay`), which is unaffected because the main tab never unloads during that flow.
- **Tests**: existing tests referencing `useAuthStore`'s `authAction`/`nextLink`/`openLoginModal` (e.g. `use-permissions.test.tsx`'s auth fixtures, `test-support/reset-stores.ts`) need updating to the new store shape.
