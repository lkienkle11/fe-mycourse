## Why

The backend (`be-mycourse`) now serves everything the signed-in homepage needs: `GET /api/v1/learner-courses/continue` (Complete your Course), `GET /api/v1/catalog/courses/trending` (Trending Course) and `GET /api/v1/catalog/instructors/popular` (Popular Instructor), all carrying the course `slug` and the owner `slug` / `owner_slug` (verified end-to-end against the dev database on 2026-10-16). The frontend `/home` route still renders the temporary placeholder `SignedInHomePage` (a title and a "temporary" notice, no API call), and the Figma design (`Homepage - 4`, node `5139:10435`) has been analysed and its scope fixed. The data contract, the design and the backend are all ready, so the placeholder can now be replaced by the real page.

## What Changes

- **Replace the placeholder** `SignedInHomePage` with the real signed-in homepage at `/home`: a three-slide hero carousel (no arrow buttons; drag/swipe and dots; auto-advances right every 3 s, restarting on manual change), **Complete your Course**, **Trending Course** and **Popular Instructor**, inside the existing `(web)` layout (existing `Header` / `Footer` are not modified). The login gate (guests see a "Sign in" call to action that goes to `/login?next=/home`) is kept.
- **Add the API client layer** for the three endpoints, reusing the existing caller factory, `apiFetch`, `useApiRowsQuery`, `buildQueryParams` and the SWR defaults: route constants (`API_PUBLIC_ROUTES.catalog.*`, `API_PRIVATE_ROUTES.course.continueLearning`), SWR keys, callers, browser bindings and hooks.
- **Add the response types** `TrendingCourseItem`, `ContinueLearningItem` (both composed from one shared `CourseOwnerSummary` and one shared course-card base) and `PopularInstructorItem`. No taxonomy field, price, discount, badge or rating is modelled, because the backend does not return them.
- **Expand More** behaves as an in-page expansion on the first release (Trending 8 → 24, Complete your Course 3 → 10, the backend maximum for each, then the button disappears). It does not navigate to a detail or list page. This is a recorded product decision; the code must carry two explanatory comments (see `design.md` D5) so a later change that introduces a detail page asks the user, through `AskUserQuestion`, whether to turn Expand More into navigation.
- **Add a temporary public placeholder route** `/courses/[slug]` (a "this page is coming soon" screen with a way back) so Trending and Complete your Course cards have a valid link target. Instructor cards are not links (no instructor page or get-by-slug endpoint exists).
- **Introduce shared UI modules only where the semantics are identical**: `SectionHeader` (title and description block repeated by home sections), `UserAvatar` (image-or-initials avatar currently copied in five places), `CourseThumbnail` (remote thumbnail with placeholder, used by two new cards) and `HomeSectionShell` (loading, empty and error handling shared by the three new sections). Existing copies are migrated to the shared module when their markup and behaviour are the same, and left alone with a written reason when they differ (`design.md`, "Capability audit").
- **Static assets**: export the hero images (slide 1 tile grid, `nguoi_hoc_thoai_mai`, `giang_vien_quay_video_online`) from Figma into `public/assets/images/home/`.
- **i18n**: replace `home.signedIn.title` and `home.signedIn.temporaryNotice` with the new section copy in `en.ts` and `vi.ts`; keep `home.signedIn.loginRequired.*`.
- **Tests**: unit tests for the callers, hooks, route helper and each component state; one Playwright journey for `/home`; fixture-server endpoints for the three APIs.
- **Documentation** (English, replace-not-append, audit stamps kept as `Prior:`): `README.md` and thirteen files under `docs/` are synchronised; `docs-update-inventory.md` lists every passage with its current and replacement text.
- Explicitly **not** changed: `/` (the guest mock home and the `src/components/home/*` mock sections), the shared `Header` / `Footer`, `next.config.ts` (remote images use the existing `unoptimized` precedent, so no `images.remotePatterns` is added), `publicCacheProfiles` (stays empty), `src/proxy.ts`, route metadata of `/home` (stays omitted per the earlier product decision), and `be-mycourse` (read-only evidence; no backend or database change is needed).
- No **BREAKING** change: the only removals are two unused message keys and the placeholder UI; no test or consumer references them.

## Capabilities

### New Capabilities

- `signed-in-home`: What a signed-in learner sees and can do on `/home`: the login gate, the hero carousel, the three data sections with their loading, empty and error states, the Expand More behaviour, field mapping and omission rules (no price, rating, badge), link rules (course cards link to the placeholder, instructor cards do not), and the avatar and thumbnail fallbacks.
- `home-catalog-contract`: How the frontend consumes the three Home endpoints: paths, authentication, `limit` defaults and maxima, response shapes, tolerance for optional and empty fields (`owner_slug` absent, `slug: ""`, missing `thumbnail_url` / `avatar`), per-user data not being cached across users, and the permission gate for the continue endpoint.
- `course-detail-placeholder`: The temporary public `/courses/[slug]` page: valid slug renders a placeholder, the page is not indexable, and it is replaced when the real course detail page is built.

### Modified Capabilities

None. No existing spec under `openspec/specs/` changes its requirements: the dashboard, auth-modal, error-handling and test-execution specs are unaffected.
